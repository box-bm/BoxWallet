# BoxWallet
It's an app to make your budget, track expenses and schedule incomes.

## CI/CD

| Workflow | Trigger | What it does |
|---|---|---|
| **PR Checks** | PR opened/updated | Validates the PR title (Conventional Commits) and runs only the unit tests related to the changed files (full suite if build files change). |
| **Main CI** | push to `main` | Full unit test suite. No versioning. |
| **Deploy** | manual | Calculates the next version from every commit/PR since the last tag, bumps `version.properties` on `main`, tags, uploads to Play **internal** (changelog + listing + mapping) and creates a **draft** GitHub release. |
| **Publish Release** | manual | After promoting to production in Play Console: publishes the draft release and marks it as **Latest**. |

### Versioning (since last `v*` tag, highest wins)

- `feat!:` / `BREAKING CHANGE` → **major**
- `feat:` / `feature:` → **minor**
- anything else (`fix:`, `perf:`, `chore:` …) → **patch**

Re-running **Deploy** with no new commits redeploys the current tag without bumping.
`bump=keep` re-ships the current `versionName` as a new build (`versionCode + 1`) and moves its tag — for iterating on a version before it reaches production.
With no `v*` tag yet, Deploy ships the current `versionName` as the first release (no bump), `versionCode + 1`.

### Play Store metadata (`fastlane/metadata/android/<locale>/`)

- `default_language.txt` (root) — Play default listing language (`en-US`); `es-419` is a translation. Optional `contact_email.txt`, `contact_website.txt`, `contact_phone.txt` are synced too.
- `title.txt`, `short_description.txt`, `full_description.txt`
- `changelogs/<versionCode>.txt` — generated by Deploy from `feat`/`fix` commits; commit one manually in a PR to override (e.g. translations). Falls back to `changelogs/default.txt`.
- `images/icon.png`, `images/featureGraphic.png`, `images/phoneScreenshots/*.png` — uploaded only if present.

Pull the current Play listing into the repo: `bundle exec fastlane supply init --json_key play-store-key.json`
